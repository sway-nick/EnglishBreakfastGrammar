# ИСТОРИЧЕСКИЕ КОНТРАКТЫ

## 1. accepted_answers

`accepted_answers` — полный список допустимых ответов.

`correct_answer` всегда должен входить в `accepted_answers`.

Test Engine проверяет ответы только по `accepted_answers`.

Test Engine не должен самостоятельно объединять или формировать список допустимых ответов.

---

## 2. Структура Option в runtime

В предыдущем обсуждении было определено:

- `value` сохраняется в CMS как provenance из WatuPRO;
- `value` отсутствует в runtime-представлении;
- в `final_lessons.json` для Option используются:
  - `option_id`
  - `order`
  - `text`
  - `is_correct`

Это исторический контракт.

Его необходимо сверить с текущей реализацией.

---

## 3. Стабильные ID

В предыдущем обсуждении было зафиксировано:

- `lesson_id`
- `exercise_id`
- `question_id`
- `gap_id`
- `option_id`

являются стабильными идентификаторами.

Они создаются при первом импорте и не должны пересоздаваться при редактировании содержимого.

ID должны сохраняться неизменными.

Этот контракт необходимо проверить на текущем pipeline.

# ИСТОРИЧЕСКАЯ АРХИТЕКТУРА GEMINI ANSWER PROCESSOR

## 4. Назначение

Gemini Answer Processor предназначен для определения правильных ответов после импорта контента в CMS.

Историческая схема:

english_cms.xlsx
    ↓
Gemini Answer Processor
    ↓
Gemini API
    ↓
внутренняя валидация
    ↓
english_cms_answered.xlsx

Исходный CMS-файл не изменяется.

---

## 5. Структура входного CMS

Исторически CMS содержала:

- Lessons
- Exercises
- Questions
- Gaps
- Options
- Explanations

Processor группировал эти данные по exercise.

---

## 6. Стратегия batching

Единица API-запроса:

один exercise = один запрос Gemini

Не:

- один question;
- один gap;
- весь lesson.

Причины, зафиксированные ранее:

- instruction даёт контекст для всех вопросов упражнения;
- вопросы одного exercise связаны общей темой;
- меньше API-вызовов;
- меньше риск потери контекста по сравнению с отправкой всего lesson.

---

## 7. Исторический поток Gemini Processor

CMS Excel
    ↓
Чтение Lessons / Exercises / Questions / Gaps / Options
    ↓
Группировка по exercise
    ↓
Построение prompt
    ↓
Gemini API
    ↓
Валидация ответа
    ↓
Запись валидных результатов в новый Excel

# ИСТОРИЧЕСКИЕ ПРАВИЛА ОТВЕТОВ

## 8. SELECT Gap

Для gap:

input_control = select

Gemini должен выбрать один существующий вариант ответа.

Ответ должен точно совпадать с текстом одного из существующих options.

После проверки:

- `correct_answer` записывается в gap;
- правильный option получает `is_correct = true`;
- остальные options получают `is_correct = false`.

---

## 9. TEXT Gap

Для gap:

input_control = text

Gemini должен определить все грамматически допустимые ответы, которые подходят именно к конкретному пропуску.

Требования:

- определить основной `correct_answer`;
- определить `accepted_answers`;
- не добавлять произвольные альтернативные формулировки;
- не менять структуру предложения;
- не менять смысл исходного задания.

Исторический пример:

She ___ a doctor.

correct_answer:
is

accepted_answers:
["is", "'s"]

---

## 10. SINGLE_CHOICE

Для вопроса `single_choice`:

- ровно один option должен быть правильным;
- только один option получает `is_correct = true`;
- остальные получают `is_correct = false`;
- gaps не изменяются.

---

# ИСТОРИЧЕСКИЙ ФОРМАТ ОТВЕТА GEMINI

## 11. Structured Output

Первоначальный формат:

{
  "gaps": {
    "gap_id": "correct_answer"
  },
  "options": {
    "option_id": true
  }
}

Позднее был уточнён формат:

{
  "gaps": {
    "gap_id": "correct_answer"
  },
  "accepted_answers": {
    "gap_id": [
      "answer1",
      "answer2"
    ]
  },
  "options": {
    "option_id": true
  }
}

`accepted_answers` должен быть связан с конкретным `gap_id`.

Не должен существовать один общий список `accepted_answers` для всего exercise.

---

# ИСТОРИЧЕСКАЯ ВАЛИДАЦИЯ

## 12. Проверка до записи

Перед записью результата Gemini необходимо проверить:

SELECT

- `correct_answer` существует среди `options.text`;
- ровно один option имеет `is_correct = true`.

SINGLE_CHOICE

- ровно один option имеет `is_correct = true`;
- gaps не изменяются.

TEXT

- `correct_answer` не пуст;
- `accepted_answers` не пуст;
- `correct_answer` входит в `accepted_answers`.

---

## 13. Некорректный ответ Gemini

Если Gemini возвращает ответ, которого нет среди существующих options:

- ничего не записывать для этого question;
- создать ERROR;
- сохранить исходные данные;
- продолжить обработку остальных batches.

---

## 14. Изоляция вопросов

Ошибка одного вопроса не должна останавливать обработку остальных вопросов exercise.

Только успешно прошедшие валидацию вопросы должны передаваться на запись.

---

# ИСТОРИЧЕСКАЯ ЗАЩИТА CMS-ФАЙЛА

## 15. Исходный Excel не изменять

Было принято решение:

english_cms.xlsx
        ↓
копия
        ↓
english_cms_answered.xlsx

Исходный CMS-файл никогда не перезаписывается.

---

## 16. Инкрементальная обработка

Уже заполненные данные должны пропускаться, если они действительно заполнены и проходят базовую проверку.

Частично заполненные или некорректные записи не должны автоматически считаться готовыми.

Такие записи должны быть повторно обработаны или отмечены как ошибки.

---

## 21. Первый реальный запуск

Первый реальный запуск должен обрабатывать только один exercise.

Исторически предлагались варианты:

--limit 1

или:

--exercise-id <id>

После первого запуска необходимо:

1. создать `english_cms_answered.xlsx`;
2. проверить изменения в Gaps;
3. проверить изменения в Options;
4. запустить CMS validation;
5. проверить результат вручную;
6. только после этого запускать остальные batches.
